# Infintor Blog Style Guide — Odoo 19

> **Reference:** Based on approved blogs by Aishwarya Menon published on infintor.com.
> Apply this guide to ALL blog creation tasks for Rohan.

---

## Core Principles

1. **Short** — 600–1000 words of body content (excluding images/FAQs). Never exceed 1200.
2. **Accurate** — Only include steps you can verify in Odoo 19. No guessing.
3. **Less Confusing** — One topic, one workflow, straight through. No tangents.

---

## What NOT To Do (Mistakes in Previous Blogs)

| Problem | Old Approach | New Approach |
|---------|-------------|--------------|
| Too long | 3000–4000+ words covering every feature | 600–1000 words covering ONE workflow |
| Too theoretical | Long intro paragraphs explaining concepts | 2–3 sentence intro, then jump to steps |
| Installation sections | "Install module X, Y, Z..." | Skip entirely — assume module is installed |
| Exhaustive feature lists | List every field, every option, every access right | Mention only what's needed for the workflow |
| Knowledge-oriented headers | "Understanding the Referral App" | Action-oriented: "Creating a Sales Order" |
| Reads like official docs | Comprehensive reference style | Blog style — guided walkthrough |
| No comparison table | Walls of text for comparisons | Use tables for side-by-side comparison |
| No FAQ | Missing | Include 3 short FAQs at the end |
| No CTA | Missing or weak | End with 1-line CTA linking to Infintor |

## Writing Rules

### Intro Paragraph
- Maximum 3 sentences
- Sentence 1: What the feature/process is
- Sentence 2: Why it matters (business impact)
- Sentence 3: What this blog covers (optional — only if scope needs clarifying)
- Do NOT include: history, general ERP philosophy, lengthy problem statements

### Navigation Steps
- Use arrow notation: `Go to Inventory App → Configuration → Warehouses → New`
- Bold the app name on first mention
- Keep each step to one line when possible
- After each navigation step, add 1 sentence explaining what happens on screen

### Explanations
- Never explain a concept for more than 2–3 sentences before moving to steps
- If a concept needs extended explanation, use bullet points (2–3 bullets, 1 line each)
- Avoid jargon dumps — if you must define a term, do it inline in one phrase

### Screenshots (Image Placeholders)
- Place `[Image: description]` after each major step
- Maximum 6–8 images per blog
- Only screenshot what adds clarity — skip obvious UI confirmations

### Headers
- Use action-oriented H2s: "Performing an Internal Transfer", "Creating a Sales Order"
- Avoid knowledge-oriented H2s: "Understanding...", "Overview of...", "About..."
- Maximum 4–5 H2 sections in the body (excluding FAQ)

### Conclusion
- 1–2 sentences maximum
- Tie back to business value (efficiency, accuracy, compliance, etc.)
- Do NOT summarize every section — the blog is already short enough

### FAQ Section
- Exactly 3 questions
- Each answer: 2–3 sentences
- Questions should be what a reader would Google about this topic
- Use bold for the question text

### Call-to-Action
- 1 line at the very end
- Format: "Looking to [verb] [topic] in Odoo 19? Connect with the experts at Infintor for a customized consultation."
- Include link to infintor.com where appropriate

## Tone & Voice

- **Directive**: "Go to...", "Click on...", "Set the...", "Navigate to..."
- **Confident**: State what happens, don't hedge with "should" or "might"
- **Professional but accessible**: No slang, but no academic stiffness either
- **Third person for Odoo**: "Odoo generates...", "The system creates..."
- **Second person for reader**: "You can then confirm the sales order"

---

## Topics That Work Well for This Format

- Single workflow: "How to [do X] in Odoo 19"
- Comparison: "[Feature A] vs [Feature B] in Odoo 19"
- Configuration guide: "Setting Up [Feature] in Odoo 19"

## Topics That Do NOT Work Well

- Full module overviews (too broad — split into multiple blogs)
- End-to-end app walkthroughs covering every feature
- Technical/developer topics (not Infintor's blog audience)
